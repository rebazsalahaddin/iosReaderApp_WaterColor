# Required cleanup after every completed chapter

The user has authorized this procedure for the whole project. Complete it after each chapter, and after a revised final edition replaces an older one. Do not request routine permission again.

1. Establish the current edition from the chapter manifest and current-progress record. Record every final image’s dimensions and SHA-256 before touching files. Preserve approval scope. Intentional matching artwork in separate story slots remains separate named output files.
2. Collect dependencies for every current final page and every future source request: manuscript, canonical references, numbered upload packs, raw sources, accepted corrections, masks, prepared components, paper insertion geometry, measured layouts, current layer files and reusable helper tools. Check recursive dependencies, not just the latest delivery folder. Preserve unreviewed returns and uncertain files until their role is established.
3. Consolidate current measured layouts under `production/chapter-NN/current/pages/PAGE_ID/layout.json`, with retained layers and source hashes. Reuse identical layers through one internal layer-store path; never depend on old review folders. Use root-relative paths. Do not use external symlinks, parent-directory assets or machine-specific absolute paths.
4. Rebuild every current page from its retained ordered layers. Compare decoded pixels against the selected final. Confirm the final PNG bytes still match the pre-cleanup hashes. Verify exact page count/order, archive entries/CRC/hashes, all supplied request attachments, canonical sources and manuscript text. Run `python3 production/validate_package.py`. Planning checks do not replace visual inspection of new artwork.
5. Write an explicit deletion inventory containing only superseded deliveries/ZIPs, unused finished candidates, temporary render previews, obsolete preparation iterations, before/after comparisons, old snapshots, caches and retired one-off tools. For each path, record the reason and file hash. Confirm every path resolves inside the project and no retained manifest, instruction, current composition or future request depends on it. Do not delete by filename age or a broad wildcard alone. Prefer updating/removing a stale reference over retaining an entire obsolete version.
6. Remove only that verified inventory. Keep ONE selected final delivery folder and at most ONE matching ZIP for each chapter. Keep necessary unique source originals, the current prepared assets/masks and all future generation packs. Repeated numbered reference images in different upload packs are intentional, useful copies; do not break the exact upload sequence to save space. Do not keep a duplicate backup tree of everything just deleted.
7. Re-run validation from the cleaned project. Confirm all pre-cleanup final image hashes and reconstruction checks still pass. Update current manifests, entry points and the current cleanup report with removed count, bytes, reason categories and remaining production work. A move/rename test is recommended after structural path changes. Delete disposable test renders and validation copies when verification finishes.

A failed dependency or pixel check stops deletion of the affected file until repaired. Unknown files are retained. Nothing outside this project root is included in this cleanup authorization.

## MCP production records

Reviewed graphical correction boards, their target specification, frozen first audit, original submitted prompt, correction block, guide manifest and issue-by-issue second-return checks are required retry evidence. Preserve them while unresolved or referenced by current source/job records; they are not temporary render previews. Never delete source/target evidence still needed to explain a paid retry. Do not manufacture graphical records retroactively for historical jobs.

Always retain production/agent-ledger.json, chapter approval history, accepted-source provenance, actual spending/job receipts and the current audits. Attempt budgets never reset during cleanup. Retain compact rejected-source evidence while a chapter or issue is unresolved; after resolution, keep its hash, verdict and correction record even if a no-longer-needed rejected image is removed. Protect references still needed by future chapters. Cleanup completion must be followed by the required manual chapter-approval stop in Higgsfield_Agent_Workflow.md.
