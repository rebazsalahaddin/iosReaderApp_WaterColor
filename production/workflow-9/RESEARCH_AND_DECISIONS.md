# Consistent illustration: investigation and decisions

Research date: 8 November 2026. Scope: the existing 27-chapter, 442-page production system, with direct failure evidence from Chapter 1. This is a workflow revision, not certification of future generated art. No paid comparison experiment was run.

## Conclusion

The project treated a reference-guided generator too much like a registered image editor. A stronger prompt cannot guarantee exact furniture, anatomy, prop counts, shadow alpha or camera placement. Keep the useful identity → posture → sibling structure, but enforce unchanged pixels in local composition and explicitly plan the geometry of each change. Spend generation credits only on missing visual content. Reuse exact accepted material wherever the story permits.

There is no evidence for a guarantee of flawless new characters, poses or illustrations within three attempts. OpenAI explicitly documents recurring-character consistency limitations and says even masks guide rather than precisely constrain an edit. The guarantee we can implement is narrower: pixels outside a reviewed local edit region remain identical to the accepted base, historical attempts cannot be reset, and incomplete checks block spending or delivery. New pixels still need visual review. [OpenAI image generation](https://developers.openai.com/api/docs/guides/image-generation)

## Evidence from this project

Seven workflow-8 jobs are terminal: one new accepted civilian-pilot identity, one accepted table neutral after two attempts, two failed standing-neutral returns and two failed imagining returns. This is a tiny, selected sample, not a statistically meaningful model ranking. It does show that identity was not the only—or even the latest dominant—failure. The standing failure was largely shadow treatment; the imagining failure was object state/count, registration and shadow preservation.

I re-inspected the complete imagining correction board, the native two-book crop and the standing result on its room backing. The existing detailed audits remain unchanged under `production/chapter-01/runs/workflow-8-v011/audits/resume-2026-11-08/`.

| Weak point | Evidence / certainty | Revision |
| --- | --- | --- |
| Exact preservation delegated to prose | Observed: the imagining return redrew supports and lost much of the parent shadow despite “EXACTLY.” | Use a registered replacement region and retain original pixels everywhere else. Never describe model guidance as a pixel lock. |
| Prop change was underspecified | Observed: neutral has a closed book far left; variant asks for an open book by the hands. It does not explicitly remove the original. Attempt 2 contains both. | Record before/after object IDs, counts, position, state and the region exposed when the old object disappears. Say replace, not merely include. |
| “Expression” included structural action | Observed: opening/moving a book, moving hands and revealing tabletop are more than a face change. | Classify face, connected action, whole contact group and new camera separately. A face-only mask cannot solve a prop replacement. |
| Board substituted for clean source | Observed: the sole reference was an opaque annotated collage, containing a reduced parent and several crops. Native transparency and registration were absent in the uploaded image. | Keep the exact clean parent as primary input on first attempts and retries. Use failure boards offline. No failed examples or diagnostic collage as the sole art authority. |
| Competing examples may encourage copying | Inference, not proven: repeated closed-book imagery and contradictory “preserve everything/open book” signals may have favored duplication. No controlled test isolated this cause. | Remove redundant negative examples from paid inputs; compile a concise target-state prompt with clear change/preserve boundaries. |
| Retry had to repeat the original prompt verbatim | The guard required complete first-prompt text in every retry, retaining ambiguity and allowing corrections to accumulate. | Freeze old prompts as evidence. Recompile a new version after a semantic diff; require all intended content and issue coverage, not contradictory verbatim accumulation. |
| Shadow failure forced regeneration of a good body | Observed: standing has useful character/paper geometry but an overly dense grey patch. Old rules prohibited any local alpha repair. | Allow a separately reviewed, reversible matte-only correction of existing shadow pixels if subject/support pixels can be protected exactly. No invented shadow or generic ellipse. |
| Shadow acceptance was insufficiently operational | “Very light” had no target-background appearance contract. Partial alpha alone was mistaken for sufficient evidence until visual review. | Inspect actual background first, plus dark/light diagnostics; distinguish core contact from broad cast shadow. Record body-safe masks, representative samples and appearance. No universal alpha threshold. |
| Neutral authority could drift before branching | Neutral parent establishes a new furniture and character rendering. A correct lineage name does not certify it matches old art. | Compare identity, two anatomical measures, rigid furniture anchors and the intended background before accepting. No successor jobs until an end-to-end representative edit passes. |
| Offline geometry was not always in the paid specification | Some exact placements remained in `audit_only_details`; the model never receives local file instructions. | Freeze a measured change plan and serialize only the necessary geometry into the submission. Reject missing/ambiguous contacts before spending. |
| Numeric tolerances risk false precision | A tilted head is not directly comparable to an upright crown/chin distance; global RGBA differences include harmless texture changes. | Use comparable landmarks with uncertainty/foreshortening notes. Exact pixel checks apply to protected composite pixels, not a claim of generated semantic identity. |
| Infrastructure validated procedure, not effectiveness | Valid boards, valid PNGs and successful jobs still produced failed art. The early variant gate was documented but incompletely machine-enforced. | Separate procedural readiness, output integrity, visual acceptance and user approval. Enforce family canary gating and attach real evidence. |
| Cost control was per source, optional per chapter | Three independent jobs could spend credits before discovering a common failure; unknown prices could default to zero in budget sums. | One live job at a time; a required bounded spend window; unknown costs fail closed. Third attempt needs a changed mechanism and a no-cost feasibility review. |
| Duplicated instructions could reinstate old rules | Hundreds of routing cards and retained migration scripts contained superseded prescriptions. | Update active routing metadata, centralize workflow precedence, retire obsolete mutation entry points and test the active contracts. Preserve historical records. |

## What the main approaches actually offer

This is a survey of the main practical families, not a claim to have tested every published system.

| Approach | Useful control | Limitation and decision for this book |
| --- | --- | --- |
| Prompt-only generation / identical seeds | Shared descriptions; reproducibility in implementations that expose the same seed and pipeline. | A seed is not a character model. Prompt changes can change anatomy and layout. Current MCP exposes no seed. Do not spend on seed hunting. |
| Clean visual reference / character sheets | Supplies visible face, hair, wardrobe, style and proportions. | Does not freeze pixels. Multi-view sheets reduce per-view pixel budget and may contain incompatible views. Audit the full identity sheet; use a suitable clean view for a foundation when justified. |
| Targeted edit / inpainting | Narrows the requested change and supplies surrounding context. | Even masks can be soft guidance. Our live connector does not expose a mask/markup field. Use a clean parent plus an offline local replacement plan; do not invent API controls. |
| Learned identity: DreamBooth / LoRA | DreamBooth personalizes a model to a subject; LoRA reduces trainable weights and storage. | Requires compatible models, curated consistent examples and training/validation. Current Flare MCP has no such training control. Poor examples would encode existing drift. A later alternative for large-volume production, not an immediate credit-saving fix. [DreamBooth](https://arxiv.org/abs/2208.12242), [Diffusers LoRA](https://huggingface.co/docs/diffusers/training/lora) |
| Image adapters / identity embeddings | IP-Adapter separates text and image conditioning; InstantID combines face identity and landmark guidance. | Useful in compatible pipelines, not switches available in Flare. Face-oriented methods do not establish this stylized child's costume, body, furniture or exact dot-eye design. Applicability here is untested. [IP-Adapter](https://arxiv.org/abs/2308.06721), [InstantID](https://instantid.github.io/) |
| Pose / edge / depth conditioning | ControlNet supports explicit spatial conditions such as edges, depth and poses. | Helps geometry, not a guarantee of identity, precise contacts or watercolor finish. Needs a compatible backend; no verified ControlNet input exists in this connector. [ControlNet](https://arxiv.org/abs/2302.05543) |
| Cross-image attention | StoryDiffusion shares information through consistent self-attention across generated images. | Requires a different pipeline and evaluation on these designs. It is not something a longer Flare prompt enables. [StoryDiffusion](https://arxiv.org/abs/2405.01434) |
| Saved elements / higher-fidelity models | Can improve convenience or source preservation. Higgsfield describes Sunburst as oriented toward precise edits. | Marketing claims do not certify this book. Live MCP quotes for medium/2K/4:3 were 1 credit each for Flare and Sunburst. Under the user-authorized workflow revision, future expression/action edits now route to Sunburst; foundations stay Flare. This is a documented task-fit choice, not a measured success-rate claim. No paid comparison was run. [Higgsfield model guide](https://higgsfield.ai/blog/gpt-image-2-6-higgsfield) |
| Layered 2D asset library / registered local edits | Reuses exact accepted pixels and measured camera transforms. | New expressions still require artwork; boundaries/occlusion must be checked. Best immediate fit for the existing assets and limited credits. This is our engineering decision, not a measured model superiority claim. |
| 2D rig / 3D scene / manual illustration | Explicit geometry and camera can be controlled; a human can repair missing drawing. | Significant setup and art direction; final watercolor rendering can drift if regenerated. Consider for the rest of the book if genuinely new viewpoints dominate. Do not build an expensive rig to solve one shadow. |

OpenAI's prompting guide recommends identifying what changes and what stays, preserving transparent output during edits, and testing the complete result. These are useful instructions, not guarantees. Our change is to turn those intentions into auditable local boundaries. [Image prompting](https://developers.openai.com/api/docs/guides/image-prompting)

## Connector capability is a separate contract

The live `models_get(gpt_image_2_6_flare)` result was saved in `research/higgsfield-flare-live-schema.json`. A catalog search verified Sunburst is model ID `gpt_image_2_6`; its schema and both exact live price quotes are in `research/model-route-comparison.json`. Both expose the same listed input controls. No quote submitted a job. It lists reference images, quality, resolution, background, batch size, output format and size-related controls. It does **not** expose mask, markup, seed, temperature, input-fidelity or separate reasoning-effort parameters. The Higgsfield website describes additional editing controls in its UI. UI documentation does not establish MCP availability. Recheck the actual tool schema before any future request; do not send guessed fields.

Native transparency also does not establish a correct shadow. In alpha compositing the foreground's color and alpha both affect the result on a new backdrop. A pale pigment with high alpha can produce a pale floor island; indiscriminately reducing all alpha can make clothing transparent. Keep source RGBA and separate a verified shadow-only region before any local correction. [W3C compositing specification](https://www.w3.org/TR/compositing-1/)

## Revised production decision

1. Route new expression/action edits to Sunburst at the verified same quoted cost, while retaining Flare foundations. Recheck actual schema/cost before use; all canonical attempts still count. Inventory/reuse and plan the exact page beat before any paid work.
2. Separate identity/style, camera/geometry, object state, contact and alpha checks. One reference cannot silently override all other authorities.
3. Use the clean accepted neutral for every sibling. A local edit is a derivative of that same parent, not a pasted head/hand from another pose.
4. For a connected action, include the entire old/new silhouette, held object, vacated area and contact boundary in the edit plan. If it cannot be integrated coherently, classify it as a whole-contact candidate and acknowledge that every regenerated feature needs review.
5. Freeze stationary furniture, feet and shadow locally wherever the edit does not affect them. Do not repair incompatible anatomy with selective warping or disconnected pieces.
6. Repair safe matte/placement issues locally before classifying an entire source as unusable. Preserve raw returns and write a new derivative audit; never rewrite historical failures as successes.
7. Validate one representative edit through actual page composition before generating siblings. No parallel speculation during recovery.
8. Maximum three global attempts, normal target one and at most one ordinary correction. A third is exceptional: documented cause, changed mechanism, feasible local integration, required estimate and budget. Never spend it just because it is available.

## What remains unproven

No workflow-9 generated illustration has yet been tested. Automated tests can prove protected-pixel preservation and budget rejection behavior, not facial identity or artistic quality. The Chapter 1 imagining source still needs a real solution for the old closed-book footprint; the standing source still needs a reviewed matte boundary before it can be locally repaired. The new policy makes those tasks possible and testable without pretending they are already complete. Neither the old delivery nor any failed source has been newly approved.
